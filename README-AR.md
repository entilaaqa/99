# موقع انطلاقة — النشر على Render مع PostgreSQL

الموقع سيرفر Node/Express واحد: يقدّم الصفحات (`index.html` و`dashboard.html`) ومسارات `/api/*`،
ويحفظ كل شيء (الحجوزات والمستخدمين والجلسات) في قاعدة **PostgreSQL على Render**. لا يعتمد على أي خدمة خارجية.
الجداول تُنشأ تلقائياً عند أول تشغيل، ولا حاجة لتشغيل أي SQL يدوياً.

## 1) ارفع المشروع إلى GitHub
ارفع محتوى هذا المجلد إلى مستودعك (الـ `.gitignore` يستثني `node_modules` و`dist` و`.env`).

## 2) أنشئ الخدمة على Render
**الطريقة الأولى (موصى بها):** Render → **New → Blueprint** → اختر المستودع. يقرأ `render.yaml` ويضبط كل شيء ثم يسألك عن قيم المتغيّرات.

**الطريقة الثانية:** Render → **New → Web Service** → اختر المستودع، ثم:

| الإعداد | القيمة |
|---|---|
| Runtime | `Node` |
| Build Command | `npm ci --include=dev && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |

## 3) متغيّرات البيئة (Environment)

| المتغيّر | القيمة |
|---|---|
| `NODE_VERSION` | `22` |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Render → قاعدتك → **Connections** → **Internal Database URL** |
| `ADMIN_EMAIL` | بريد المدير الأول |
| `ADMIN_PASSWORD` | كلمة مرور المدير (10 أحرف على الأقل) |

ملاحظات:
- استخدم **Internal Database URL** إن كانت الخدمة وقاعدة البيانات في **نفس الـ Region** (أسرع وأأمن). إن اختلف الـ Region استخدم **External Database URL**؛ الكود يكتشف الحالتين ويفعّل SSL تلقائياً عند الحاجة.
- عند كل تشغيل يُنشأ حساب المدير إن لم يكن موجوداً. **لتغيير كلمة مرور المدير** غيّر `ADMIN_PASSWORD` فقط وسيُحدَّث الحساب وتُنهى جلساته القديمة.

## 4) تأكّد أن كل شيء يعمل
1. `https://اسم-خدمتك.onrender.com/healthz` ← يظهر `ok`.
2. `/api/bookings` ← يظهر `"db":"connected"`. عند الفشل يظهر `reason` يوضّح السبب (`no_db_url` = المتغيّر ناقص، `db_connect` = الرابط خاطئ أو القاعدة غير متاحة).
3. جرّب الفورم من الصفحة الرئيسية، ثم سجّل الدخول وافتح لوحة التحكم.

## 5) المستخدمون والصلاحيات
- **مدير (`admin`)**: يرى كل شيء، يصدّر CSV، ويدير المستخدمين.
- **فريق العمل (`team`)**: عرض ومتابعة العملاء (الحالة والملاحظات) بدون تصدير وبدون إدارة مستخدمين.
- يضيف المدير المستخدمين من الداشبورد: **الإعدادات ← المستخدمون** (إضافة، تغيير كلمة المرور، تغيير الدور، تعطيل، حذف). لا يمكن حذف آخر مدير ولا تعطيل حسابك بنفسك.
- مسارات الداشبورد: `/dashboard.html#/overview` · `#/leads` · `#/settings/profile` · `#/settings/users`

## 6) الدومين
Render → Settings → **Custom Domains** → أضف `entilaaqa.com` واتبع سجلات DNS.

## الأمان
- كلمات المرور مشفّرة بـ scrypt، والجلسات في PostgreSQL (يُحفظ منها SHA-256 فقط) بكوكي `HttpOnly` + `Secure` + `SameSite=Lax` وتنتهي بعد 7 أيام من عدم الاستخدام.
- تحديد المحاولات: 8 محاولات دخول فاشلة لكل بريد (و30 لكل IP) كل 15 دقيقة، و10 حجوزات/ساعة لكل IP.
- رفض الطلبات القادمة من مواقع أخرى (فحص Origin)، وترويسات أمان وCSP وHSTS.
- السيرفر يقدّم فقط الملفات الموجودة في `public/` المصرّح بها (لا يُكشف `src` ولا `package.json`).
- حماية honeypot من البوتات، والتحقق من كل الحقول في السيرفر، ومنع تكرار الحجز عند إعادة الإرسال.

## ملاحظات Render
- الخطة المجانية للخدمة تنام بعد 15 دقيقة بلا زيارات وأول زيارة بعدها تتأخر قليلاً.
- **تحقق من خطة قاعدة البيانات:** قواعد PostgreSQL المجانية على Render لها مدة صلاحية محددة (حوالي 30 يوماً) وقد تُحذف بعد انتهائها. للبيانات الحقيقية استخدم خطة مدفوعة، أو خذ نسخة احتياطية دورياً.
- إن ظهرت للزائر رسالة «تعذّر تثبيت الحجز» فراجع **Render → Logs** وصفحة `/api/bookings`.

## التشغيل محلياً
```bash
cp .env.example .env        # عبّئ DATABASE_URL (رابط External من Render أو Postgres محلي)
npm install
npm run typecheck
npm run dev                 # يقرأ .env ويعيد التشغيل عند التعديل
```
ثم افتح `http://localhost:3000`.

## بنية الملفات
| الملف | وظيفته |
|---|---|
| `src/server.ts` | سيرفر Express: الصفحات الثابتة + API + فحص الصحة + إيقاف آمن |
| `src/db.ts` | اتصال PostgreSQL، إنشاء الجداول تلقائياً، إنشاء حساب المدير |
| `src/auth.ts` · `src/password.ts` | الجلسات وتحديد المحاولات وتشفير كلمات المرور |
| `src/routes/bookings.ts` | استقبال الحجوزات وحفظها |
| `src/routes/login.ts` · `me.ts` · `users.ts` | تسجيل الدخول، بيانات الداشبورد، إدارة المستخدمين |
| `public/` | `index.html` · `dashboard.html` · PWA (`sw.js`, `manifest.webmanifest`, `icons/`) |
| `render.yaml` | إعداد Render (Blueprint) |
